## 패턴 분석

### Keep (유지)
- **실측 우선**: 문서·추론 대신 실제 API/Obsidian 앱으로 확인 → 가설 오류(UX-5 대체 경로, 4xx 오류 형태)를 조기에 발견.
- **수정 전/후 나란히 비교**: 같은 시나리오를 직전 릴리즈 빌드와 새 빌드로 돌려 회귀를 "차이"로 판정 → 기존 동작 불변을 객관적으로 입증.
- **특성화(characterization) 테스트로 원인 재현** 후 spec 작성 — 코드 수정 없이 근거 확보.
- **작업 스트림 격리**: git worktree로 배포분·docs·차기 spec을 분리해 PR 오염 방지.
- **커밋 이력으로 설계 의도 복원**(`git log -S/-G`): 호출별 토큰 한도, 링크 방식 변천, 단일 노트 200 누락 원인을 정확히 설명.

### Drop (중단)
- **벤더 권고를 프로젝트 결정 확인 없이 적용** (temperature). 
- **배포된 기능의 제거를 의도·노출 확인 없이 제안** (aiMaxTokens).
- **실측 1회 결과로 "확실히 고장" 단정** — 계정 의존 오류(2.5-pro)를 일반화.
- **테스트 하네스 자체 버그**(구 어댑터 복사 시 내부 참조 미치환)로 baseline 1회 무효 — 비교 하네스도 스모크 검증 필요.

### Try (시도)
- 외부 가이드 적용 전 `git log -S <파라미터>` + ADR 검색을 체크리스트화.
- 실기기 E2E를 `/release` Step 3에 정식 편입(TD-5).
- 결론 표현에 검증 범위(계정·횟수·환경)를 함께 표기.
